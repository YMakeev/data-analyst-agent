# Гілка workshop-start

Це каркас, який ми заповнюємо разом на воркшопі. Тут навмисно не написані
саме ті шматки, які набираються в кадрі, — решта (база, генератор даних,
тренування моделі, деплой) уже готова.

## Порядок

Підготовку (`make setup`, `make test`) роби **на гілці `main`** — там усе
працює, і ти переконаєшся, що оточення в порядку. На початку воркшопу:

```bash
git checkout workshop-start
```

База, дані й модель від перемикання гілки нікуди не діваються — вони живуть
у Docker і в `ml/model.pkl`, а не в git.

## Тести як специфікація

```bash
make test
```

Зараз багато червоного — це нормально. Тести описують, що саме має робити
кожна функція, тому ними зручно звірятись:

- `tests/test_sql_guard.py` — що guard мусить відбити і, не менш важливо,
  чого він чіпати НЕ мусить
- `tests/test_tools_smoke.py` — яку форму має повертати кожен інструмент

## Якщо відстала

```bash
git checkout main
```

Повне рішення. Повернутись назад можна будь-коли:

```bash
git checkout workshop-start
```

Нічого не втратиться — база й модель спільні для обох гілок.
