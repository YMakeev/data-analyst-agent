# Якщо не працює

## Спершу запусти самоперевірку

```bash
make doctor
```

Команда перевірить оточення, підключення до бази й наявність моделі та
скаже, що саме не так. Здебільшого відповідь буде вже там, і далі читати
не доведеться.

Далі — розбір за симптомами, від найчастішого.

---

## Claude не бачить сервер

Симптом: у Claude Desktop немає інструментів, або він каже, що не має доступу
до бази.

**1. Ти перезапустила Claude Desktop повністю?**
Не «закрила вікно», а вийшла із застосунку: `Cmd+Q` на Mac, іконка в треї →
Quit на Windows. Конфіг читається тільки при старті процесу.

**2. У конфізі абсолютні шляхи?**
Claude Desktop запускає сервер не з твоєї папки, тому `python` і `.` він
розуміє інакше, ніж термінал. Не пиши шляхи руками:

```bash
make config
```

Ця команда друкує готовий JSON саме для твоєї машини.

**3. JSON валідний?**
Зайва кома або дужка ламають весь файл мовчки. Перевір:

```bash
python3 -m json.tool ~/Library/Application\ Support/Claude/claude_desktop_config.json
```

**4. Подивись логи Claude Desktop.** Там видно справжню причину:

```bash
# macOS
tail -50 ~/Library/Logs/Claude/mcp-server-ai-analyst.log
# Windows
# %APPDATA%\Claude\logs\
```

## Сервер падає при старті

Перевір його поза Claude — там помилки видно одразу:

```bash
make run
```

Якщо процес мовчки висить і нічого не друкує — це **нормально**. Сервер чекає
команд по stdin. Зупини через `Ctrl+C`.

Типові помилки:

| Текст | Причина |
|---|---|
| `Не задано DATABASE_URL` | немає `.env` → `cp .env.example .env` |
| `No module named 'server'` | запускаєш не з кореня проєкту, або не з того Python |
| `No module named 'mcp'` | залежності не встановлені → `make setup` |
| `connection refused` | база не піднята → `docker compose up -d` |

## База не піднімається

```bash
docker compose ps        # статус
docker compose logs db   # що саме сталось
```

**`port is already allocated`** — на 5433 уже щось висить. Знайди що:

```bash
lsof -i :5433
```

Або зміни порт у `docker-compose.yml` і синхронно в `.env` (обидва DSN).

**`Cannot connect to the Docker daemon`** — Docker Desktop не запущений.

**Схема не створилась** (таблиць немає) — файли з `db/init/` виконуються
**лише при першому створенні** тому. Якщо ти їх правила після першого запуску:

```bash
make reset
```

## Claude дає неправильні цифри

Це не поломка, це урок.

Спершу подивись, чи він узагалі викликав `describe_table`. Якщо ні — він не
бачив коментарів до колонок, де описані пастки. Скажи прямо: «спочатку подивись
структуру таблиці».

Якщо викликав, а все одно помилився — подивись, що саме написано в коментарі
до потрібної колонки. Ймовірно, там недостатньо явно. Допиши й перевір ще раз:

```sql
COMMENT ON COLUMN lessons.status IS 'нове пояснення';
```

Коментар змінюється без рестарту сервера — `describe_table` читає його з бази
щоразу. Це найшвидший цикл зворотного зв'язку в усьому проєкті: правиш опис
даних і одразу бачиш іншу відповідь моделі.

## Тести падають

```bash
make test
```

- **Усі тести з базою пропущені** (`skipped`) — база не піднята, це очікувано.
- **`test_lesson_count_trap_is_material` впав** — дані згенерувались
  неправильно, зроби `make reset`.
- **Тести guard падають** — ти щось змінила в `server/db.py`; подивись, який
  саме запит перестав відбиватись.

## Нічого з переліченого не допомогло

```bash
make reset
```

Зносить базу разом із томом і збирає все з нуля. Займає ті самі дві хвилини.
Нічого твого це не чіпає — усе живе всередині Docker.
