# Винести сервер у хмару

Поки сервер живе на твоєму комп'ютері, ним користуєшся тільки ти: він
запускається разом із Claude Desktop і вимикається разом із ним.

Після деплою все інакше. Сервер крутиться в хмарі цілодобово, а колеги просто
додають одне посилання у себе в Claude. Їм не треба ні Python, ні цей
репозиторій, ні пароль від бази — доступ до неї лишається на сервері.

Приблизно 15 хвилин. Хостинг коштує близько $5 на місяць.

---

## Що зміниться в коді

Нічого. Серйозно — жодного рядка.

Локально Claude Desktop **сам запускає** сервер як дочірню програму й
спілкується з ним через стандартні потоки введення й виведення. У хмарі
запускати нема кому: контейнер стартує сам, а клієнти приходять до нього по
мережі. Тому сервер має слухати мережевий порт.

Перемикає це одна змінна оточення, `MCP_TRANSPORT`. Ось усе місце в коді, яке
про неї знає ([server/main.py](../server/main.py)):

```python
if transport in ("http", "streamable-http"):
    mcp.run(transport="streamable-http", host=host, port=port)
else:
    mcp.run(transport="stdio")
```

## Крок 1. Свій репозиторій

Хостинг збирає програму з репозиторію на GitHub, тому потрібен свій.

Якщо цей проєкт ти клонувала — зроби форк на GitHub і переприв'яжи свою копію:

```bash
git remote set-url origin https://github.com/ТВІЙ_НІК/data-analyst-agent.git
git push -u origin main
```

**Перевір, що у сховище не поїхали паролі.** Файл `.env` навмисно внесений до
списку ігнорованих, але переконайся:

```bash
git ls-files | grep "^\.env$" && echo "УВАГА: пароль у репозиторії" || echo "чисто"
```

## Крок 2. Проєкт на Railway

Зареєструйся на [railway.com](https://railway.com) і створи проєкт:

**New Project** → **Deploy from GitHub repo** → обери свій репозиторій, гілка
`main`.

Railway попросить доступ до репозиторію — дай. Далі він сам знайде файл
`railway.toml` у корені, зрозуміє, що збирати треба з `deploy/Dockerfile`, і
почне збірку.

## Крок 3. Змінні оточення

У сервісі → вкладка **Variables** → додай рівно дві:

| Змінна | Значення |
|---|---|
| `DATABASE_URL` | той самий рядок підключення, що в твоєму `.env` |
| `MCP_TRANSPORT` | `http` |

Без другої змінної контейнер підніметься, чекатиме команд зі стандартного
введення й мовчатиме. На панелі буде написано «сервіс працює», а підключитись
до нього не вийде — найзаплутаніша з можливих поломок.

**Нічого більше не додавай.** Зокрема:

- `ADMIN_DATABASE_URL` — не потрібен. Сервер лише читає дані, і адмінського
  доступу в хмарі не має бути взагалі: якщо сервер колись зламають, узяти з
  нього права на запис буде нізвідки.
- `SEED_ON_START` — заповнює базу заново. У базі вже є дані, і зайвий
  перезапуск із цією змінною їх перезапише.

Якщо база у тебе локальна в Docker, вона з хмари недосяжна — для деплою
знадобиться база в мережі. Розділ «Своя база в хмарі» в кінці цієї сторінки.

## Крок 4. Відкрити доступ ззовні

**Settings** → **Networking** → **Generate Domain**.

Цей крок легко пропустити, а без нього нічого не працює: Railway за
замовчуванням не видає сервісу публічної адреси, тож сервер живий, але ззовні
його не існує.

Отримаєш адресу виду `data-analyst-agent-production-xxxx.up.railway.app`.
Робоче посилання — з `/mcp` у кінці:

```
https://твоя-адреса.up.railway.app/mcp
```

## Крок 5. Перевірити, що сервер відповідає

```bash
curl -sS -X POST https://твоя-адреса.up.railway.app/mcp -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
```

У відповіді має бути `ai-analyst`.

Якщо відкрити цю адресу просто в браузері, побачиш
`Bad Request: Missing session ID`. Це **правильна** відповідь, а не поломка:
протокол вимагає спершу привітатись, а браузер просто запитує сторінку.

## Крок 6. Підключити в Claude

Налаштування Claude → **Connectors** → **Add custom connector** → назва й
посилання з `/mcp`.

Далі новий чат і питання «що є в цій базі?». Те саме посилання можна дати
колегам — вони додають його так само й одразу працюють.

---

## Якщо не працює

Відкрий логи деплою на Railway — там видно причину дослівно. Орієнтири:

| У логах | Що це означає |
|---|---|
| `==> База відповідає` | підключення в порядку, шукай далі |
| `!! База недосяжна після 12 спроб` | невірний `DATABASE_URL` або база не пускає ззовні |
| `Стартую MCP-сервер на порту` | сервер піднявся, перевіряй адресу й `/mcp` |
| `Модель не знайдено` | у поставку не потрапив файл `ml/model.pkl` |

Останній випадок означає, що модель не була натренована до збірки. Вона —
частина поставки, а не те, що створюється в хмарі:

```bash
make train
git add ml/model.pkl && git commit -m "натренована модель" && git push
```

## Про безпеку, коротко

Після деплою адреса публічна: підключитись зможе будь-хто, хто її знає.

Для навчальної бази із вигаданими даними це прийнятно. Для справжніх робочих
даних — ні, і додати вхід за паролем тут **обов'язково** до того, як
підключати реальну базу. Що саме робити — [deploy/AUTH.md](../deploy/AUTH.md).

Користувач бази, під яким працює сервер, уміє лише читати — це захищає дані
від псування. Але від чужих очей він не захищає жодним чином.

## Своя база в хмарі

Потрібна, якщо локальна база в Docker, а сервер у хмарі: контейнер до твого
комп'ютера не достукається.

Заводиш безкоштовний проєкт на [neon.com](https://neon.com), створюєш у ньому
**окрему** базу (не ту, де лежить щось важливе) і розгортаєш туди структуру й
дані:

```bash
python db/bootstrap.py --dsn "рядок-адміністратора"
python db/seed.py --dsn "рядок-адміністратора"
```

Перший скрипт створює таблиці й окремого користувача `analyst_ro` з правом
лише читати, а потім друкує готовий рядок підключення саме для нього — ось
його і клади в `DATABASE_URL`.

**Не клади туди рядок адміністратора**, який хмара видає за замовчуванням.
Він працюватиме, і саме тому це небезпечно: усе виглядатиме справним, але
агент отримає право змінювати й видаляти дані. Перевірити, що користувач
справді обмежений:

```bash
python scripts/prove_readonly.py
```

П'ять відмов і один дозвіл на читання — правильний результат.
