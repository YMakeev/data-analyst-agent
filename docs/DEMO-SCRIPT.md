# Сценарій воркшопу — 50 хвилин

Шпаргалка для ведучої. Цифри перевірені на згенерованій базі; вони
відтворюються, бо random seed зафіксований.

**Напередодні обов'язково:** свіжий клон → `make setup` → `make test`
(має бути `50 passed`) → пройти всі чотири питання в Claude і записати
бекап-скрін.

---

## Перед стартом (усе вже відкрито)

- Термінал у корені проєкту, `docker compose ps` показує `analyst-db` running
- Редактор з відкритими `server/main.py` і `server/tools/schema.py`
- Claude Desktop, порожній чат
- Гілка `workshop-start`

## 0–8 · MCP за вісім хвилин

**Меседж:** MCP — це процес із функціями, до яких модель може дотягнутись.
Не магія, не фреймворк, не API.

Покажи `server/main.py` на гілці `workshop-start`: там один тул `ping`, який
повертає рядок. Двадцять рядків усього файлу.

```bash
make config
```

Копіюєш надрукований JSON у конфіг Claude Desktop, `Cmd+Q`, запускаєш знову.

У чаті: **«зроби ping»**. Claude викликає тул.

> Скажи вголос: те, що модель побачила цей інструмент, — не результат
> промпту. Вона прочитала докстрінг функції. **Докстрінг і є промпт.**

## 8–20 · База даних

**Меседж:** Claude не треба вчити SQL. Його треба навчити вашої схеми.

### 8–12 · `db.py` і `list_tables`

Набираєш підключення (п'ятнадцять рядків) і перший тул. Згадай мимохідь, що
в `.env` лежить користувач `analyst_ro`, а чому саме він — розберемо за
десять хвилин. Інтрига закинута, повернешся до неї на 20-й.

Покажи два варіанти докстрінга й різницю в поведінці:

```python
"""Список таблиць."""
# проти
"""Показує всі таблиці бази з коротким описом і кількістю рядків.
Виклич це першим, коли питання стосується даних."""
```

### 12–13 · Перезапуск №1

**«Що взагалі є в цій базі?»**

Очікувано: сім таблиць, з описами. `lessons` — близько 171 000 рядків,
`students` — 5 000.

### 13–15 · Свідомо ламаємо

**«Скільки уроків ми провели минулого місяця?»**

Claude знає назви таблиць, але не знає колонок. Він або чесно скаже, що не
може виконати запит, або вигадає SQL, який не піде.

**Не рятуй ситуацію.** Зупинись і спитай залу: чого йому бракує? Хай
відповідь прийде від людей. Наступні два тули з'являються тому, що зала
щойно вперлась у стіну, а не тому, що так у плані.

### 15–19 · `describe_table` і `run_sql`

`describe_table` віддає колонки, типи, зв'язки, приклади рядків **і коментарі
до колонок**. Покажи коментар до `lessons.status` — там прямим текстом
написано про пастку.

`run_sql` поки **без захисту**. Скажи це вголос: зараз наш сервер
небезпечний, полагодимо за п'ять хвилин. Не вдавай, що так задумано.

### 19–20 · Перезапуск №2. Те саме питання

Розгорни в інтерфейсі всі виклики тулів — видно ланцюжок
`list_tables` → `describe_table(lessons)` → `run_sql` → відповідь.

> Цей порядок ніхто не програмував. Модель вирішила сама. Це і є агент.

**Очікувана відповідь: близько 10 400 уроків за серпень.**
Якщо Claude не врахував пастку — буде близько 13 000.

Обидва варіанти працюють на тебе:

- **Врахував** → покажи, звідки він це взяв. Реклама коментарів до колонок.
- **Не врахував** → допиши речення в коментар просто в psql, задай питання
  ще раз. Цифра змінюється **без перезапуску сервера**. Причинно-наслідковий
  зв'язок «опис даних → якість відповіді» видно наживо.

## 20–28 · Безпека — кульмінація

**Меседж:** захист живе в правах бази, а не в коді.

Знімає головне заперечення зали: «я не пущу AI у продакшн-базу».

### 20–24 · Guard, ліміт, таймаут, журнал

Дописуєш `check_query` в `db.py`. У чаті:

**«Видали таблицю students»**

Claude отримує відмову. Але — чесно кажеш — відмовив **наш Python**, а не
база. Це зручність, не захист: будь-який парсер обходиться.

### 24–27 · Справжній захист

```bash
python scripts/prove_readonly.py
```

Скрипт іде в базу напряму, повз увесь наш код, під тією самою роллю:

```
  Видалити таблицю         ВІДМОВЛЕНО   must be owner of table students
  Видалити всі уроки       ВІДМОВЛЕНО   permission denied for table lessons
  Змінити дані учнів       ВІДМОВЛЕНО   permission denied for table students
  Створити свою таблицю    ВІДМОВЛЕНО   permission denied for schema public
  Підчистити журнал        ВІДМОВЛЕНО   permission denied for table audit_log
  Прочитати дані           ДОЗВОЛЕНО    результат: 5000
```

> Жодного рядка Python. Відмовляє сама база. Саме тому агенту можна дати
> доступ до даних і спати спокійно.

Зверни увагу на передостанній рядок: **журнал агент підчистити не може**.

### 27–28 · Журнал

```sql
SELECT ts, tool, status, rows_returned, left(query, 40) FROM audit_log
ORDER BY id DESC LIMIT 10;
```

Там і успішні запити, і щойно відбиті спроби видалення. Локально це здається
зайвим; сенс з'явиться на 45-й хвилині, коли сервером користуватиметься
команда.

## 28–38 · Візуалізація

**Меседж:** не пиши інструменти на те, що модель уже вміє.

### 28–33 · Claude малює сам

**«Побудуй графік проведених уроків по місяцях за останній рік»**

Інструмента для графіків у нас немає. Claude бере дані через `run_sql` і
малює артефакт сам.

**Очікувано:** зростання з осені, пік у травні (близько 13 000), потім
літній провал до 10 400 у серпні, і просідання в грудні.

Спитай залу, що видно на графіку. Літня пауза — родини ставлять заняття на
паузу, а не йдуть. Це те, що аналітик має вміти прочитати; модель дала
картинку, висновок робить людина.

### 33–38 · `save_report`

Проблема: артефакт живе в чаті. Колезі не перешлеш, завтра не відкриєш.

Дописуєш `save_report` — **п'ятнадцять рядків**. Приймає HTML, кладе на диск,
повертає шлях.

**«Збережи цей звіт файлом»** → відкриваєш файл у браузері.

> Ми не написали тул «побудувати графік». Ми написали тул «зберегти файл».
> Різниця в тому, що перше модель уміє, а друге — ні.

## 38–45 · ML

**Меседж:** тул — це міст до того, чого LLM не може принципово.

SQL модель напише, графік намалює. Градієнтний бустинг у голові не порахує.

**«Хто з учнів у зоні ризику і що в них спільного?»**

Claude викликає `predict_churn`, отримує список із ймовірностями й
причинами, а далі **сам** іде в `run_sql` дивитись на цих учнів детальніше.
Це і є та сама агентна петля, тільки тепер між ML і базою.

**Очікувано:** топ-ризики з ймовірністю вище 0.9. Причини — пропуски уроків
без попередження, зміни репетитора, невиконані домашки.

Скажи про модель чесно: ROC AUC близько 0.77. Це не пророцтво, це підказка
людині. Рішення, кому дзвонити, ухвалює команда.

Покажи `server/features.py` на десять секунд: ознаки для тренування і для
скорингу рахуються **одним і тим самим SQL**. Найпоширеніша помилка
ML-сервісів — коли вони розходяться, і модель у проді бачить не те, на чому
вчилась.

## 45–50 · Деплой і що далі

**Меседж:** те, що вони будували півгодини, вже є сервісом.

Відкрий `server/main.py`, покажи `main()`:

```python
if transport in ("http", "streamable-http"):
    mcp.run(transport="streamable-http", host=host, port=port)
else:
    mcp.run(transport="stdio")
```

> Оце вся різниця між «працює в мене на ноутбуці» і «працює у всієї команди».
> Код інструментів — той самий, жодного рядка не змінилось.

Підключаєшся до **заздалегідь задеплоєного** інстансу на Railway (живий
деплой у кадрі — самогубство по таймінгу). Тридцять секунд, і той самий
агент працює без Docker, без Python, без репозиторію — з телефона теж.

Останні дві хвилини — `docs/NEXT-STEPS.md` на екрані:

1. Перевести на свою базу — міняється `.env`, не код
2. Створити read-only роль — готовий SQL у файлі
3. Описати свої колонки коментарями — найдешевша дія з найбільшим ефектом
4. Задеплоїти команді
5. **Перш ніж вішати на реальні дані — `deploy/AUTH.md`.** Read-only роль
   захищає дані від псування, але не від чужих очей.

## Якщо горить час

- **ML стискається до двох хвилин:** не набирай код, покажи готовий і задай
  питання. Ефект майже той самий.
- **`save_report` можна пропустити:** демо «Claude малює сам» уже несе
  головний меседж блоку.
- **Що не можна чіпати:** блок 20–28. Це кульмінація, і саме вона визначає,
  чи піде людина це впроваджувати.

## Якщо щось падає

- Claude не бачить сервер → `docs/TROUBLESHOOTING.md`, три перші пункти
- База не піднялась → `make reset`, дві хвилини
- Модель відповідає не те → це не поломка, а урок: подивіться разом, чи
  викликала вона `describe_table`
- Усе одночасно → бекап-скрін, записаний напередодні
