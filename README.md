# AI-аналітик: MCP-сервер над базою даних

Воркшоп **From Data to AI Engineer** — 50 хвилин, за які ми з нуля будуємо
MCP-сервер, що дає Claude доступ до бази даних, і деплоїмо його для команди.

Claude отримує пʼять інструментів: подивитись, які є таблиці, прочитати їхню
структуру, виконати SQL-запит на читання, зберегти звіт і звернутись до
ML-моделі. Далі він сам вирішує, що і в якому порядку викликати.

Попередні знання про MCP не потрібні.

---

## Швидкий старт

Потрібні **Docker** і **Python 3.10+**. Перевірка й установка — у
[docs/SETUP.md](docs/SETUP.md).

```bash
git clone <url> && cd data-analyst-agent
python -m venv .venv && source .venv/bin/activate
make setup
```

`make setup` підніме Postgres у Docker, поставить залежності, згенерує
демо-дані й натренує churn-модель. Займає 2–3 хвилини.

Далі підключаємо сервер до Claude Desktop:

```bash
make config
```

Команда надрукує готовий JSON з правильними шляхами саме для твоєї машини —
скопіюй його у файл конфігурації Claude Desktop і **повністю перезапусти
застосунок** (Cmd+Q, не просто закрити вікно).

Перевірка: спитай у Claude «що є в цій базі?». Якщо він перелічив таблиці —
все працює.

## Що всередині

```

  main.py        реєстрація інструментів і вибір транспорту
  db.py          пул, SQL-guard, дружні помилки
  features.py    ознаки churn-моделі (спільні для тренування і скорингу)
  audit.py       журнал звернень агента
  tools/         власне інструменти

  init/          схема з коментарями + read-only роль (виконуються Docker'ом)
  seed.py        генератор синтетичних даних
```

## Інструменти

| Інструмент | Що робить |
|---|---|
| `list_tables` | таблиці бази з описами й кількістю рядків |
| `describe_table` | колонки, типи, звʼязки, приклади і коментарі з поясненнями |
| `run_sql` | SELECT-запит: guard, ліміт, таймаут, запис у журнал |
| `save_report` | зберігає HTML-звіт, який Claude згенерував сам |
| `predict_churn` | ризик відтоку учня + причини |

Графіків серед інструментів немає навмисно. Claude малює візуалізації краще,
ніж це зробив би тул із параметрами «тип, вісь X, вісь Y». Наша справа —
зберегти результат у файл, щоб його можна було переслати колезі.

## Безпека

Сервер ходить у базу під роллю `analyst_ro`, яка має право **лише читати**
(плюс додавати рядки в журнал). Спроба видалити чи змінити дані впирається
в права Postgres, а не в перевірку в коді.

SQL-guard у [server/db.py](server/db.py) — додаткова зручність: він
відхиляє очевидно небезпечний запит і повертає моделі зрозуміле пояснення
замість сирого винятку. Але захист — це права ролі, а не guard.

Кожен виклик пишеться в `audit_log`: що питали, скільки рядків повернули,
скільки це тривало. Видаляти звідти агент не може.

## Дані

Синтетичний сервіс онлайн-репетиторства: учні, репетитори, підписки, уроки,
платежі, звернення в підтримку. Приблизно 5 000 учнів і 240 000 уроків за
18 місяців.

Дані в git не зберігаються — комітиться генератор із фіксованим random seed,
тому база в усіх однакова. Період рахується відносно сьогоднішньої дати, тож
дані завжди свіжі.

У схему навмисно закладені пастки, через які наївний запит дає правдоподібну,
але неправильну цифру: тестові акаунти, чотири статуси уроку, повернені
платежі. Усі вони описані в коментарях до колонок, які `describe_table`
віддає моделі.

## Команди

```bash
make setup    # повний сетап з нуля
make config   # JSON для Claude Desktop
make test     # тести
make reset    # знести базу і зібрати заново
make run      # запустити сервер вручну (для дебагу)
```
